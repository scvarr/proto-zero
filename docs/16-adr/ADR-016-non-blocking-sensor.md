# ADR-016: Non-blocking Sensor — рождение времени

**Статус:** accepted
**Дата:** 2026-02-28
**Связанные:** [ADR-006-life-as-blocking-loop](../06-adr/ADR-006-life-as-blocking-loop.md), [ADR-004-no-time-no-memory](../04-adr/ADR-004-no-time-no-memory.md), [ADR-015-crisis-of-silence](../15-adr/ADR-015-crisis-of-silence.md)

---

## Контекст

ADR-015 зафиксировал **Crisis of Silence**: агент не способен отличить молчание мира от насыщения.
Причина — blocking read (ADR-006): при отсутствии данных в stdin вызов `read()` блокирует навсегда.
Агент «заморожен» внутри syscall и не может наблюдать отсутствие стимула.

Три состояния реальности:
- **Данные есть** → `read()` возвращает `n > 0` → обработка.
- **Данных нет, pipe открыт** → `read()` блокирует бесконечно → агент заморожен.
- **EOF** → `read()` возвращает `n = 0` → смерть.

Состояние «тишина» существует в мире, но агент его не наблюдает.

---

## Эволюция инварианта

ADR-004 установил: «нет времени». Этот инвариант был верен для организма, который не нуждался в различении тишины.

ADR-015 показал: без различения тишины агент теряет чувствительность. **Организм просит время.**

Инвариант «нет времени» снимается. На его место приходит:
- **Время агента = счётчик попыток восприятия** (тиков сенсора), а не физические секунды.
- Каждая попытка чтения stdin — один квант внутреннего времени, независимо от результата.

---

## Решение

Заменить blocking read на **non-blocking read** с тиковым циклом:

```rust
pub fn run_sensor_loop<F>(mut on_tick: F) -> io::Result<()>
where
    F: FnMut(SensorEvent),
```

Где `SensorEvent`:
```rust
pub enum SensorEvent<'a> {
    /// Данные получены — стимул.
    Data(&'a [u8]),
    /// Попытка чтения не вернула данных — тишина.
    Silence,
}
```

Цикл жизни:
1. Установить stdin в non-blocking режим.
2. В бесконечном цикле: попытка `read()`.
   - `n > 0` → `on_tick(SensorEvent::Data(&buf[..n]))`.
   - `WouldBlock` → `on_tick(SensorEvent::Silence)`.
   - `n == 0` (EOF) → возврат (смерть).

---

## Что меняется

| Было (ADR-006) | Стало (ADR-016) |
|---|---|
| `run_stdin_forever(on_chunk: FnMut(&[u8]))` | `run_sensor_loop(on_tick: FnMut(SensorEvent))` |
| Blocking read — агент спит при тишине | Non-blocking read — агент «дышит» |
| Два состояния: данные / смерть | Три состояния: данные / тишина / смерть |
| Нет времени | Время = счётчик тиков |

---

## Инварианты

- **Время агента ≠ физическое время.** Нет таймеров, sleep, clock. Время — это число попыток чтения.
- Симметрия black/white сохраняется.
- BLACK остаётся немым.
- Односторонний поток world → agent сохраняется.
- Drive bounded в [0, 1) сохраняется.
- Кадровое состояние (frame) сбрасывается на `\n`.

---

## Следствия

1. Агент впервые **наблюдает отсутствие** — различает «мир молчит» и «мир насыщает».
2. Открывается путь для **event-based decay** (угасание drive при тишине) — будущий ADR.
3. `evaluate_stdin_once()` остаётся для тестов/утилит без изменений.
4. World не требует изменений — он просто перестаёт писать, и агент это чувствует.

---

## Acceptance-критерии

1. При непрерывном потоке от world поведение drive идентично текущему.
2. При прекращении потока (world замолкает) агент продолжает тикать и вызывает `on_tick(Silence)`.
3. При возобновлении потока агент снова получает `Data(...)`.
4. Тесты подтверждают все три состояния.
5. Симметрия black/white сохранена.
