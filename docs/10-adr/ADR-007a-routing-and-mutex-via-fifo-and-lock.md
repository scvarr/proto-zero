# ADR-007a: Маршрутизация world→agent через FIFO + взаимная блокировка стеками

**Статус:** accepted  
**Дата:** 2025-10-12  
**Связанные:** ADR-001a, ADR-005, ADR-006, ADR-007

## Контекст
Агенты читают только из stdin. Нам нужна операционная маршрутизация потока stdout `world` → stdin *одного* выбранного агента (black *или* white) и способ исключить их одновременный запуск.

## Решение
1) **Маршрутизация через FIFO (именованный pipe) и shell-шим** на уровне `docker-compose`:
    - Сервис `fifo-init` создаёт `/io/stream` (общий том `pz-io`).
    - `world` пишет в FIFO, агент читает `cat /io/stream | <agent>`.
    - Код агентов не меняется (stdin как единственный транспорт).

2) **Взаимная блокировка стеков** без изменения агентов:
    - Вводится общий том `pz-lock` и сервисы `lock-black` / `lock-white`, создающие файлы `/lock/BLACK` или `/lock/WHITE`.
    - Перед стартом агента shell-шим проверяет конфликтующий лок и аварийно завершает запуск при конфликте.
    - Лок-файлы создаются *не агентами* (соблюдение этики и инвариантов).

## Обоснование
- Не нарушаем инварианты Stage-0 (нет времени/памяти в агентах, нет сетей).
- Изоляция агентов сохраняется: синхронизация и маршрутизация вынесены «за пределы» (оркестрация).
- Простая операторская модель: два compose-файла (`world+black` и `world+white`).

## Последствия
- Остаются два явных сценария запуска (по одному агенту).
- Для переключения между стеками требуется остановка текущего и, при необходимости, очистка тома `pz-lock`.

## Альтернативы (отклонены)
- Общий `compose` с профилями без блокировок — не гарантирует эксклюзивность.
- Ведение лока самим агентом — противоречит запретам на внешние эффекты у `black` и роли `white`.

## Инварианты
- Агенты не создают файлов/сокетов, не пишут наружу (кроме метрик у white).
- Канал односторонний: `world.stdout → agent.stdin`.
