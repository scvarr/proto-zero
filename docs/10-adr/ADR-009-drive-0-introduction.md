# ADR-009: Введение первого драйва (drive.0)

**Статус:** accepted  
**Дата:** 2025-10-12  
**Связанные:** ADR-006, ADR-007, ADR-008

---

## Контекст

После кризиса перенасыщения наблюдения (ADR-008) агенты существуют в постоянном потоке данных, но не различают интенсивность или длительность стимулов.  
Необходимо минимальное внутреннее состояние, отражающее *накопление входного возбуждения*.

---

## Решение

Ввести **первый драйв (`drive.0`)** — внутреннюю скалярную величину, изменяемую в ответ на поступление данных.

### У black
- Вводится переменная `drive_0: f64`.
- Каждый раз при успешном чтении байтов stdin `drive_0` увеличивается на фиксированный дельта-шаг (`+1.0`).
- Значение нигде не логируется и не выводится (инвариант этики сохраняется).
- При EOF — процесс завершается, драйв исчезает (нет памяти между запусками).

### У white
- Та же логика накопления `drive_0`, но значение логируется в метриках.
- Метрика:
  ```json
  {
    "agent": "white",
    "stage": "Stage-1",
    "sensor": { "has_any": true },
    "drive": { "0": <value> }
  }
