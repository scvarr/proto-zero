# ADR-006: Кризис «нет жизни» → бесконечная готовность (blocking loop)

**Статус**: accepted \
**Дата**: 2025-10-11

## Контекст

Stage-0 реализован как единичное «ощупывание» stdin и завершение процесса. Агент не «живёт»: нет длительного существования, нет непрерывной готовности к восприятию.

## Решение

Ввести **блокирующий цикл чтения stdin** как форму «жизни»:
- **без времени** (никаких таймеров/тики/задержек);
- **без памяти** (каждое событие обрабатывается независимо; не накапливаем состояние);
- **без вывода** у black (по-прежнему немой);
- **white** имеет право логировать **по событию** (одна JSON-строка на успешное чтение ≥1 байта).
- 
**Смерть процесса** = закрытие stdin (EOF) или остановка контейнера.

## Инварианты, которые сохраняются

Нет явного времени (нет sleep, нет счётчиков). \
Нет памяти (нет накопления, стейт не сохраняется). \
Нет моторов/выходов у black.

## Операционные условия

- Контейнеры запускаются с stdin_open: true (docker) — чтобы чтение блокировало, а не получало мгновенный EOF.
- Источник мира (позже: контейнер world) будет подавать данные в stdin.

## Последствия

- black — «жизнь» = постоянная готовность, слив входа в «никуда».
- white — поток метрик (по одной строке JSON на событие).
- Завершение = docker stop или закрытие stdin (EOF).

## Связанные ADR
- ADR-001a (транспорт сенсора = stdin).
- ADR-005 (изоляция контейнеров black/white).
- (план) ADR-007 «мир как отдельный контейнер».
