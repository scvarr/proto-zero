# ADR-011: Drive Regulation Mechanism

**Статус:** accepted  
**Дата:** 2025-10-12  
**Связанные:** [[ADR-009-drive-0-introduction]], [[ADR-010-crisis-of-drive-saturation]]

---

## Контекст

ADR-010 зафиксировал кризис бесконечного роста `drive.0` при непрерывном потоке стимулов.  
Необходимо ввести внутренний регулятор, который стабилизирует `drive.0` без нарушения инвариантов:

- нет времени;
- нет долговременной памяти;
- симметрия `black/white`;
- отсутствие моторов/внешних эффектов у `black`.

---

## Цели

- Предотвратить неограниченный рост `drive.0`;
- Сохранить локальную детерминированность (только функция входа);
- Обеспечить наблюдаемую метрику у `white` без искажения динамики;
- Не вводить побочных источников (время, случайность, состояние вне цикла чтения).

---

## Варианты (на этапе анализа)

1. **Leak-per-chunk**  
   `drive_0 = max(0.0, drive_0 + 1.0 - λ)`

2. **Saturating growth**  
   `drive_0 += α / (1.0 + β * drive_0)` — естественное насыщение, плавное ограничение роста.

3. **Cap-bounded**  
   `drive_0 = min(cap, drive_0 + 1.0)` — жёсткая сатурация.

---

## Критерии выбора

- Минимальная вычислительная сложность;
- Сохранение симметрии black/white;
- Возможность наблюдения эффекта регуляции у `white`;
- Этичность (`black` не получает моторов или выходов);
- Возможность детерминированной эволюции при любых входах.

---

## Решение

Принята **параметр-свободная регуляция** с нормировкой `drive.0 ∈ [0, 1)` и событийным обновлением:
$$
d \leftarrow \frac{1}{2 - d}
$$

Вывод из событийного счётчика:  
$$
d = \frac{n}{n + 1}\Rightarrow n' = n + 1 \Rightarrow d' = \frac{n + 1}{n + 2} = \frac{1}{2 - d}
$$
Константа «2» — **структурная** (из \(n+2\)), не тюнинговая.  
При появлении параметров, из которых она выводится, будет ревизия.

---

## Bounded semantics of drive (без параметров)

Мы фиксируем пространство состояний drive как **компакт [0,1]**, где:
- `0` — нулевое возбуждение (отсутствие свидетельств),
- `1` — полное насыщение (определяется выбором единиц; нормировка, а не тюнинг).

**Обоснования:**

1. **Нормировка по единице мощности** — выбираем единицы так, что saturation ≡ 1.
2. **Комбинаторный вывод** — \(d = n/(n+1) ∈ [0,1)\), \(n∈ℕ₀\); при событии \(d ← 1/(2−d)\).
3. **Вероятностная семантика** — drive трактуется как вероятность возбуждения ⇒ значения в [0,1].
4. **Конвексность/миксинг** — [0,1] замкнут под конвексными комбинациями, обеспечивая будущую масштабируемость.
5. **Компактность без времени** — при отсутствии времени устойчивость итераций требует компактного инвариантного множества.

Следствие: [0,1] — **каноническая шкала без тюнинга**.  
Любая монотонная репараметризация допустима как эквивалентная шкала.

---

## Свойства модели

- Ограниченность: $0 ≤ d < 1 \Rightarrow 0.5 ≤ d' < 1;$
- Монотонность и сублинейный прирост;
- Идемпотентность по батчингу (композиция по событию ассоциативна);
- Без скрытых параметров: единственная константа выводится из структуры события.

---

## Изменения в коде (Stage-2)

- В ядре: чистая функция `drive_update(d)`:
  ```rust
  #[inline]
  pub fn drive_update(d: f64) -> f64 {
      let next = 1.0 / (2.0 - d);
      next.clamp(0.0, 1.0 - f64::EPSILON)
  }
