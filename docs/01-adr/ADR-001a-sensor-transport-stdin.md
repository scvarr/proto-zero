# ADR-001a: Транспорт сенсора на Stage-0 — stdin

**Статус:** accepted  
**Дата:** 2025-10-11  
**Связанные:** [ADR-000-null-core](../00-core/ADR-000-null-core.md), [ADR-001-minimal-input-ephemeral](./ADR-001-minimal-input-ephemeral.md),[ADR-004-no-time-no-memory](../04-adr/ADR-004-no-time-no-memory.md), [ADR-005-container-isolate](../05-adr/ADR-005-container-isolate.md), [ADR-006-life-as-blocking-loop](../06-adr/ADR-006-life-as-blocking-loop.md)

## Контекст
На Stage-0 агенту доступен только факт наличия данных. Нам нужен минимальный, этичный и универсальный способ доставки этого факта в процесс агента без времени, памяти и побочных каналов.

## Решение
Использовать **stdin** процесса как единственный транспорт сенсора:
- `has_any == true` фиксируется, когда прочитан ≥1 байт.
- Отсутствие данных означает блокирующее ожидание.
- EOF интерпретируется как завершение «жизни» процесса.

## Обоснование
- **Минимализм и переносимость:** stdin есть везде, не требует сетевых стеков.
- **Сохранение инвариантов:** нет времени (ожидание блокирующее), нет памяти (ничего не накапливаем), нет вывода у `black`.
- **Этика:** отсутствуют скрытые двусторонние каналы; направление строго «в мир → агент».

## Последствия
- Контейнеры должны запускаться с открытым stdin (`stdin_open: true`).
- Любые альтернативные транспорты (CLI-флаги, сокеты, файлы, сети) запрещены на Stage-0 и могут появиться только через отдельный кризис/ADR.

## Альтернативы (отклонены)
- **CLI-флаг `--has-any`:** разовый, не даёт «жизни» и событийности.
- **TCP/Unix-сокеты:** преждевременно усложняют и вводят скрытые каналы.
- **Файлы/каталоги:** добавляют состояние/согласование и риск утечек.

## Инварианты
- Нет времени, нет памяти, у `black` нет вывода; `white` логирует только метрики наблюдения.
